# Balanced Boolean development experiment (fixed before generation)
Date 2026-11-25. Exploratory redesign after known failures, not a preregistered final benchmark. Preserve previous experiments and all failures. Never read prior 66 test tasks or use them in split construction, tuning, model choice or inference. Their overlap with new tasks is therefore unknown and they must not be claimed pristine independent test after this work.
Public grammar x,y,z, AND/OR/NOT, depth2, 125 mechanistic keys and eight input truth tables from generator/validator v1. Enumerate unique full truth tables (not test-instance answer sets); partition by anchor bit at 000 independently and deterministically: for each anchor 0 and 1, sort truth signatures by SHA256(`balanced-truth-split-v1:`+eight-bit signature), allocate first ceil(70%) to train and remaining dev. This prevents same generating full truth across groups; same valid structures and possible behavior overlap across distinct partially observed questions are allowed, explicitly audit, not leakage by itself.
For each truth table enumerate every 4- and 5-observation subset including 000. Same exact observation assignment generated by both groups is ambiguous: exclude it from both. Also exclude both observations when 4-observation task in one group is a subset of any 5-observation task in the other. Then fixed, outcome-blind per-stratum stable SHA256(`balanced-task-select-v1:` + canonical task ID) ranking: target up to 32 train and 10 dev per (anchor bit, observation count), with no replacement, giving at most 128 train and 40 dev. If a stratum lacks enough, keep all, report realized imbalance; never replace with duplicates. No filtering based on label answer count; enumerate solution count only for post-selection audits. Label only new train examples; developer gold generated for offline scoring after generation, never for training or prompt, no old-test data. Audit original previous 129 train overlap with new dev in public observations and actual full truth identities; old adapter comparison always marked contaminated if overlap; do not modify split based on old adapter performance.
