# ReclaimHypo：约束生成与共享预算回收

**Constraint-Guided Budget Recycling** · 一个统一调度器，三个任务适配器。

[实验报告](report.md) · [两分钟汇报稿](presentation/两分钟汇报稿.md) · [来源说明](PROVENANCE.md)

本实验验证：在相同总输出预算下，小解空间问题耗尽后，将名额分给仍有合法新答案的问题。统一后端支持因果图、引力体素、布尔表达式。

**本实验允许因果、布尔、体素跨题型共用预算，也允许每题输出数不同；不能替代固定每题6次或各题型独立预算的结果。主要提升来自约束工具和预算分配，不是新训练。** 原方案和本实验所有结果分别保存。

## 实测结论

18道内部测试题，总输出名额108：固定每题6个得到64个不同合法答案、44个重复；共享预算得到108个不同合法答案、零重复。合法率均100%，按题平均恢复率65.43%→74.49%。其中体素恢复率22.22%→42.59%，因果与布尔保持100%恢复。

去重率按实际输出数计算：共享策略三个任务都是100%；各题分母已经改变。对照“耗尽即停但不重分配”只输出64个，去重率也100%，覆盖完全没增加；因此需要同时查看输出数和不同合法答案数。

## 一次复跑

建议Python3.9至3.11，在本目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-cpu.txt
PYTHON_BIN="$PWD/.venv/bin/python" bash reproduce_cpu.sh
```

脚本拒绝覆盖已有运行目录。包含17项新测试、9项冻结后端测试，及3批题集×6种题目顺序×3策略，共54批、720个题目运行。已有完整输出见`final_results/`。当前一键脚本要求结果目录位于本包内，使用默认目录即可。

推理与评分是两个独立进程。推理进程只读`query_only_inputs.json`，通过Python文件读取审计阻止读取项目下其他JSON/JSONL，包括参考答案、候选池和答案数量；这个审计是防止意外读取的检查，不是对恶意代码的安全沙箱。

## 代码

- `budget_v1/scheduler.py`：持续生成不同合法机制，逐题轮转，空间耗尽后回收名额。无gold/pool/S输入。
- `budget_v1/prepare.py`：从原数据抽取观测和公共规则，冻结输入与代码哈希。
- `budget_v1/run_inference.py`：只接触观测的推理进程，保存完整输出、求解次数和耗时。
- `budget_v1/evaluate.py`：推理后才读取参考答案，以原始任务验证器核验。
- `certified_generation_v1/exact_backend.py`：上一轮冻结的三个约束适配器；布尔仍枚举公共语法。
- `final_results/protocol.json`：预算、顺序、来源与运行代码哈希。
- `report.md`：详细结果、指标分母、成本和局限。

## 范围

19开发题、18内部测试题、3道四节点因果压力题均来自已使用过的数据。五个额外顺序种子不是训练种子，不证明新题泛化。这里没有加载LLM、训练或占用GPU；也没有证明模型参数能力提升。基于同一约束后端，比较三种预算策略；总输出数相同，不代表CPU计算量相同。

随包提供原始任务生成器与冻结验证器。

一般评分会保存空解和超时的部分结果；空解恢复率为未定义，并单列数量。复现脚本随后额外要求冻结40题实验全部达标，失败也保留已经写出的评分。运行协议未单列冻结对照JSON和评分配置JSON的哈希；这两份文件包含在总文件哈希清单中。
